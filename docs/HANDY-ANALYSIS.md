# Handy: разбор кодовой базы и что взять в whisper-station

Дата: 2026-11-10. Разбирали Handy **0.10.0** (commit `73cc857`, 2026-11-06),
лицензия **MIT**. Наш проект — `whisper-station` 0.3.1, GPL-3.0, Python 3.12 +
PySide6. Разбор сделан по исходникам, а не по README: все ссылки ниже — на файлы
в `src-tauri/src/` Handy и на наши модули.

Лицензии: Handy — MIT, мы — GPL-3.0. MIT совместим с GPL, но код мы не копируем:
идеи и алгоритмы переписываем на Python. Если позже понадобится перенести
фрагмент дословно, сохраним copyright notice Handy.

## 0. Коротко

- Handy — это **Tauri 2 + Rust (36,6 тыс. строк) + React/TypeScript (23,5 тыс.
  строк)**, 348 Rust-тестов, 26 локалей. Модели (Whisper/Parakeet/…) считаются
  **внутри процесса**, в отдельном worker-процессе `transcribe-cpp`.
- На Linux Handy сознательно **урезан**: глобальный хоткей — через настройки
  рабочего стола (`handy --toggle-transcription`), оверлей по умолчанию
  **выключен**, вставка по умолчанию — **прямой набор текста**, а не Ctrl+V.
  KGlobalAccel не используется вообще.
- Наш проект уже сильнее Handy именно в KDE/Wayland: нативный хоткей с
  press/release, HUD с осциллограммой, живой предпросмотр, systemd, doctor,
  пакет. Ломать это не нужно.
- Забирать надо **не стек и не архитектуру**, а 8–10 приёмов: режим
  «тап/удержание», словарь с нечёткой коррекцией, чистку текста, историю,
  хук на транскрипцию, auto-submit, задержки и защиту вставки, probe синтаксиса
  ydotool, аккуратные настройки/уведомления.
- Ориентир по объёму: P0 (0.4) — около **3–4 дней**, P1 (0.5) — ещё **4,5–5,5 дней**.

Поток данных Handy:

```
shortcut → coordinator (режим/порог) → audio (16 кГц mono, VAD)
        → transcribe.cpp worker → текст → custom words → filler removal
        → hook → clipboard/paste → история (SQLite)
```

Ключевое отличие от нас: у Handy **модель и VAD внутри приложения**, поэтому
есть streaming, точные VAD-вероятности и отдельный supervisor. У нас модель
живёт в общем faster-whisper HTTP-сервере на `127.0.0.1:8765`; это осознанное
решение (переиспользование модели, падение модели не роняет GUI). Поэтому
большая часть «модельной» архитектуры Handy нам **не нужна**.

## 3. Как сделаны ключевые вещи

### 3.1 Режимы хоткея

`ShortcutActivation::{Toggle, PushToTalk, HoldOrToggle}` — по умолчанию
**HoldOrToggle** (`settings.rs:176-185`). Порог — 300 мс
(`settings.rs:584`). Логика в `transcription_coordinator.rs:470-489`:

```rust
let held = released_at - pressed_at;
if held >= threshold { stop_and_transcribe(); }   // удержание
else { hold.locked = true; }                     // тап: запись остаётся
```

Дальше «locked»-сессия игнорирует отпускание, а следующее нажатие её
останавливает. Есть debounce 30 мс, release grace 50 мс (против X11
auto-repeat), запоминание нажатия, пришедшего во время распознавания
(`:126-149`). Это чистая машина состояний, которую легко тестировать.

**Важно:** Handy не использует KGlobalAccel. На Linux у него
`tauri-plugin-global-shortcut`, который на Wayland не работает, поэтому
документация предлагает назначить `handy --toggle-transcription` в DE. Наш
`hotkey.py` уже получает и press, и release от KGlobalAccel (проверено,
`docs/DECISIONS.md`), поэтому hybrid нам доступен без evdev.

### 3.2 Вставка и буфер

Порядок в `clipboard.rs:74-138`:

1. Прочитать буфер: сначала текст; картинку — только если текста нет.
2. Записать текст (`wl-copy` на Wayland; `wl-copy` запускается с
   `Stdio::null()`, иначе его демон держит pipe и читатель виснет).
3. Подождать `paste_delay_ms` (60 мс).
4. Послать сочетание: на KDE Wayland — `kwtype` (KDE Fake Input), иначе
   `wtype` (не на KDE/GNOME), затем `dotool`, затем `ydotool`; на X11 —
   `xdotool`, затем `ydotool`; в конце enigo.
5. Подождать `paste_delay_after_ms` (60 мс).
6. Восстановить буфер: текст → картинка → `clear()`, если было пусто.
   Восстановление выполняется **до** проброса ошибки вставки.

Ценные мелочи:

- **`PASTE_LOCK`** (`clipboard.rs:20,823`) — все вставки сериализованы, иначе
  две одновременные вставки восстанавливают буфер друг друга.
- **Probe синтаксиса ydotool** (`:307-379`): `ydotool key --help` один раз,
  symbolic (`ctrl+v`, 0.x) vs raw (`29:1 47:1 47:0 29:0`, 1.x+), при
  неопознанном выводе — raw, ошибки не кэшировать.
- **`--`** перед текстом во внешних инструментах, чтобы текст на `-` не был принят за
  флаг; для dotool — построчный stdin, чтобы переводы строк не выполнялись как
  команды.
- **Reliable paste** (ожидание фактического чтения буфера) есть только для
  macOS/Windows (`paste_tx/`), на Linux его нет: Wayland не даёт receipt.
  Наш фиксированный `restore_delay_ms` — тот же компромисс.

### 3.3 Текст после распознавания

Порядок в `managers/transcription.rs:1638-1700`:

1. (CJK) конвертация письменности.
2. **Custom words** — `audio_toolkit/text.rs:151-220`.
3. **Filler removal** — `text.rs:429-468`.
4. **Stutter collapse + whitespace** — `text.rs:330-365,470-480`.
5. Hook (см. ниже).

Custom words — самый интересный алгоритм:

- нормализация слова (alnum, lower), n-граммы до 3 слов, склейка без пробелов
  («Charge B» → `chargeb` → «ChargeBee»);
- ограничение разницы длин 25 % (минимум 2 символа);
- Levenshtein, нормированный на длину; Soundex-бонус ×0.3 для ASCII;
- порог по умолчанию **0.18**;
- сохранение регистра и пунктуации вокруг слова;
- `&` → `and` как дополнительный ключ;
- CJK и не-ASCII fuzzy не трогает.

Filler removal двухуровневый: универсальные не-слова (`uh`, `uhm`, `hmm`,
`хм`, `ммм`) удаляются всегда; языковые (`um/ah/eh` для en, `äh/ähm` для de,
`euh` для fr) — только при наличии свидетельства языка. При удалении
заглавного филлера в начале предложения заглавная буква передаётся следующему
слову. Это аккуратная деталь, которую стоит сохранить.

### 3.4 История

Схема (`managers/history.rs:22-40`):

```sql
transcription_history(
  id, file_name, timestamp, saved, title, transcription_text,
  post_processed_text, post_process_prompt, post_process_requested,
  source_name, language, language_source
)
```

Плюсы: хранится и сырой, и обработанный текст, и промпт, и источник
(диктовка/файл), и причина выбора языка. Аудио лежит рядом в `recordings/`.
UI: бесконечная прокрутка по 30, star, copy, play, retry, удаление, retention
по количеству или возрасту. Поиска по тексту в Handy **нет** — это как раз то,
что мы можем сделать лучше.

Для нас аудио хранить не нужно (принцип «аудио не пишем на диск»), достаточно
текста, языка, длительности и источника. SQLite из стандартной библиотеки, WAL,
поиск по нормализованному тексту.

### 3.5 Hook

`<app data>/hooks/transcription` — исполняемый файл. Handy пишет текст в stdin,
читает stdout, снимает один завершающий перевод строки; пустой вывод — не
вставлять ничего; ошибка/таймаут 30 с — вставить исходный текст
(`transcription_hook.rs`). Это дешёвый и мощный extension point: транслит,
замена терминов, локальная LLM, форматирование под приложение.

### 3.6 VAD и чанкинг

Silero 0.3, frame 512 (32 мс), pre-roll 450 мс, onset 60 мс, hangover 450 мс
(1650 мс для streaming), без auto-stop (`audio_toolkit/vad/smoothed.rs`).
Long-form chunking: целевой чанк 30 с, максимум 40 с, минимум 5 с, резка в
середине самой длинной паузы, **без overlap** (`audio_toolkit/chunking.rs`).

У нас VAD уже делает сервер (`vad_filter=True` в `server.py`), поэтому
клиентский VAD не даст заметного выигрыша. Чанкинг мог бы помочь на 30-минутных
записях, но сервер и так обрабатывает длинное аудио; это оптимизация на потом,
а не функция.

### 3.7 Оверлей

Handy использует `gtk-layer-shell`, `Layer::Overlay`,
`KeyboardMode::None`, `focusable(false)` (`overlay.rs:143-168`), позиционирует
якорями, а не координатами. На Linux оверлей **по умолчанию выключен**, потому
что композитор может считать его активным окном и тогда вставка уходит не туда
(README). У нас HUD, наоборот, забирает фокус — иначе не работают Esc и кнопки;
перед вставкой HUD прячется. Это другой, но рабочий компромисс. Копировать
«оверлей без фокуса» стоит только вместе с глобальным Esc, иначе получим худший
UX.

### 3.8 Настройки, ошибки, i18n

- 70+ полей, `serde(default)` на контейнере, миграции по
  `settings_schema_version`, salvage: одна битая настройка не сбрасывает
  остальные (`settings.rs:1174-1340`).
- Ошибки: Rust отдаёт **коды**, UI — тексты; одна notice на источник, тост +
  footer + трей (`notices.rs`). Для нашего масштаба это оверкилл, но принцип
  «код в ядре, текст в UI» полезен, если будем делать en-локаль.
- i18n: 26 локалей, CI проверяет паритет ключей. Нам достаточно ru/en, но
  сам `check-translations` — хороший пример.

## 5. Что берём

### P0 — версия 0.4 «Текст и режимы» (3–4 дня)

#### 5.1 Hybrid-режим (тап/удержание)

Зачем: один хоткей закрывает оба сценария — короткая заметка тапом и
push-to-talk удержанием; это лучший UX-паттерн Handy.

Как:

- `Config.hotkey_mode`: добавить `"hybrid"`; `Config.hold_threshold_ms = 300`
  (секция `[hotkey]`).
- `Controller`: `_pressed_at`, `_locked`; на release:
  `held >= threshold → stop()`, иначе `_locked = True`; следующее нажатие при
  `_locked` → `stop()`. Отпускание во время `STARTING`: короткое — запомнить
  `_locked` и дать записи начаться, длинное — `cancel()`.
- HUD: показывать `LOCK` вместо `REC` в locked-сессии (по желанию).
- Тесты: тап фиксирует, удержание стопает, второй тап стопает, release во
  время старта.
- Оценка: 0,5 дня.

#### 5.2 Словарь и чистка текста

Зачем: Whisper на русских именах/терминах ошибается; пост-коррекция — то, что
реально улучшает вывод без смены сервера.

Как:

- Новый `whisper_station/textproc.py` (чистые функции, без Qt):
  `apply_custom_words`, `remove_filler_words`, `collapse_stutters`,
  `normalize_text`, `process_text`.
- Секции конфига:
  `[dictionary] words = [...]`, `threshold = 0.18`;
  `[text] remove_fillers = true`, `collapse_stutters = true`,
  `trailing_space = false`.
- Алгоритм: n-граммы 1–3, нормализация alnum/casefold, Levenshtein с
  ограничением длины 25 %, порог 0.18, сохранение регистра/пунктуации.
  Для кириллицы — то же расстояние Левенштейна, без Soundex.
- Filler: универсальные `ээ/эм/ммм/хм/uh/uhm/hmm`, языковые `um/ah/eh` (en);
  список пользователя переопределяет встроенный.
- Stutter: 3+ одинаковых подряд (только буквенные слова).
- UI: вкладка/группа «Словарь» — список слов, добавить/удалить, порог.
- Тесты: таблица кейсов (точное, fuzzy, n-gram, пунктуация, регистр, кириллица,
  ложные срабатывания).
- Ограничение: сервер игнорирует `prompt`; это только пост-коррекция.
  Если когда-нибудь в `server.py` появится поле `prompt`/`hotwords`, качество
  вырастет — зафиксировать в `docs/TASKS.md`.
- Оценка: 1,5 дня.

#### 5.3 Вставка: задержки, auto-submit, trailing space, lock

Зачем: убрать гонку «wl-copy ещё не отдал данные» и дать сценарий «продиктовал
и отправил» для чатов.

Как:

- `[insert] pre_delay_ms = 60`, `post_delay_ms = 60`,
  `auto_submit = "off" | "enter" | "ctrl+enter"`.
- `inject.py`: `threading.Lock()` вокруг всей вставки; `time.sleep` до/после;
  после успешной вставки — `ydotool key` для Enter/Ctrl+Enter.
- Auto-submit **по умолчанию off** и с предупреждением в UI: Enter уйдёт в
  активное окно.
- `trailing_space` применять к тексту до вставки.
- `ydotool` probe: `ydotool key --help` после старта `ydotoold`, классифицировать
  raw/symbolic, кэшировать успех; fallback raw.
- Тесты: последовательность вызовов, auto-submit только при успехе, lock,
  классификатор help-текста.
- Оценка: 1 день.

#### 5.4 Hook на транскрипцию

Зачем: дешёвый Unix-extension point без изменения ядра.

Как:

- `whisper_station/hooks.py`: путь
  `~/.config/whisper-station/hooks/transcription`; если файл исполняемый —
  запустить с текстом в stdin, timeout 30 с, снять один `\n`; пустой stdout —
  не вставлять; ошибка — исходный текст + warning в лог.
- `[hooks] enabled = true` (чтобы можно было отключить, не удаляя файл).
- Выполнять в фоновом потоке распознавания, не в UI: hook может думать до 30 с.
- `doctor`: строка «hook» — есть/нет/не исполняемый.
- Тесты: успех, неисполняемый, ненулевой код, пустой вывод, timeout.
- Оценка: 0,5 дня.

#### 5.5 Трей: быстрый язык

Зачем: переключение ru/en/auto без открытия настроек.

Как: подменю «Язык» с `QActionGroup`, при выборе — `save(cfg)`,
`controller.cfg = cfg`, `preview.cfg = cfg`; уведомление не нужно.
Оценка: 0,25 дня.

### P1 — версия 0.5 «История и удобство» (4,5–5,5 дней)

#### 5.6 История (SQLite, без аудио)

- `whisper_station/history.py`: `sqlite3`, WAL, `user_version`, таблица
  `entries(id, created_at, text, text_norm, language, duration_ms, source)`;

## 6. Что не берём

- **Tauri/React/Rust-стек** — переписывание ради переписывания; наш PySide6
  уже даёт трей, HUD и настройки.
- **Модели внутри процесса, engine supervisor, скачивание моделей** — у нас
  внешний сервер; его жизненный цикл, VRAM и загрузка — не наша зона.
- **VAD/streaming/чанкинг** — сервер уже делает `vad_filter`; streaming через
  HTTP-эндпоинт не даёт дешёвого partial-результата.
- **Облачная LLM-постобработка** — нарушает правило «только loopback»;
  локальный hook покрывает легитимные сценарии.
- **Онбординг, updater, 26 локалей, What's New** — для single-user приложения
  это лишний вес; doctor + README достаточно.
- **Reliable paste** — на Wayland нет receipt; остаёмся на задержке.
- **Оверлей без фокуса** — у нас HUD с фокусом и Esc; менять только вместе с
  глобальным cancel-хоткеем.
- **`ModelUnloadTimeout`, GPU-устройства, каталог моделей** — зона сервера.
- **`always_on_microphone`, mute while recording, clamshell, AirPods** —
  кросс-платформенные/железные сценарии, не наш профиль.

## 8. Риски и открытые вопросы

1. **KGlobalAccel release.** Наш `docs/DECISIONS.md` фиксирует проверенные
   press/release; если на другой версии KWin release не придёт, hybrid
   деградирует до toggle. Нужен тест на живой сессии и честная запись в README.
2. **Auto-submit** может отправить сообщение не в то окно. Default off,
   предупреждение, не включать вместе с `clipboard`-режимом без текста.
3. **Hook** исполняет пользовательский файл. Это его файл и его ответственность;
   не запускать от root, не использовать shell, таймаут.
4. **История** хранит текст на диске. По умолчанию — 100 записей/30 дней,
   кнопка очистки, возможность выключить; не хранить аудио.
5. **Custom words** могут ложно срабатывать. Порог 0.18, ограничение длины,
   список пользователя; при сомнении — выключить.
6. **Сервер игнорирует `prompt`.** Пост-коррекция — единственный путь без
   изменения `.whisper-local`. Если появится возможность добавить поле
   `prompt`/`hotwords` в `server.py`, это стоит согласовать отдельно.
7. **SQLite и потоки.** WAL + `busy_timeout`, запись из главного потока,
   чтение из UI; не открывать соединение на каждый чих без нужды.
8. **Рост настроек.** Поэтому вкладки в 0.5, а не ещё один длинный диалог.

## 9. Что предлагаю начать делать

Порядок с максимальным эффектом на день затрат:

1. **Словарь + чистка текста** (0.4, 1,5 дня) — сразу заметно на именах и
   терминах.
2. **Hybrid-режим** (0.4, 0,5 дня) — лучший UX хоткея.
3. **Задержки вставки + ydotool probe** (0.4, 0,5 дня) — меньше «иногда не
   вставилось».
4. **Hook** (0.4, 0,5 дня) — расширяемость без кода.
5. **История** (0.5, 2,5–3 дня) — самая крупная, но и самая полезная
   пользовательская функция после самой диктовки.

Если делать только одно — **словарь**; если два — **словарь + hybrid**.
