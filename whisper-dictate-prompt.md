# Промпт для агента: локальное приложение диктовки для CachyOS

Скопируйте всё, что ниже, в задачу другому агенту. Это самодостаточное ТЗ: контекст,
что уже работает, что нужно сделать, какие ограничения проверить и как принять результат.

---

## Задача

Сделать нативное Linux-приложение **`whisper-dictate`** для CachyOS (Arch-based, KDE Plasma 6,
Wayland): по глобальному хоткею (и по кнопке в трее) записывать микрофон, распознавать речь
**локальной моделью Whisper** и вставлять текст в активное окно. С минимальным GUI: иконка в
трее, маленький HUD во время записи, окно настроек. Без облака, без телеметрии, без DSH в
зависимостях.

На выходе — устанавливаемый пакет (PKGBUILD + `.desktop` + иконка), который работает сам по
себе, даже если DeepSeek Harness закрыт, и переиспользует уже скачанную модель, а не качает
вторую копию.

## Что уже есть на машине (проверить, не переделывать)

Всё лежит в `/home/av/Documents/dsh-set/.whisper-local/`:

| Компонент | Детали |
|---|---|
| Модель | `models/` — faster-whisper **large-v3-turbo**, ~1.6 ГБ, скачана с HuggingFace |
| Python | `.venv` — Python 3.12.14, `faster-whisper 1.2.1`, `ctranslate2 4.8.4` |
| GPU | CUDA 12 cuBLAS 12.9 + cuDNN 9.27 внутри `.venv/lib/.../nvidia`; `run.sh` выставляет `LD_LIBRARY_PATH`; сервер сам выбирает `cuda/float16` или `cpu/int8` с fallback |
| Сервис | `server.py` (FastAPI) на `127.0.0.1:8765` |
| Запуск | `run.sh` (env: `WHISPER_PORT`, `WHISPER_MODEL`, `WHISPER_DEVICE=auto|cpu|cuda`, `WHISPER_PARENT_PID`, `WHISPER_IDLE_SECONDS`) |
| Словарь | `prompt.txt` — подсказка `initial_prompt` для терминов/имён, читается на каждой транскрипции |
| Лог | `server.log` |

HTTP-контракт (OpenAI-совместимый, проверен):

```sh
curl -s http://127.0.0.1:8765/health
# {"status":"ok","model":"large-v3-turbo","device":"cuda","compute_type":"float16",
#  "pid":25428,"parentPid":2222,"idleSeconds":1800,"error":null}

curl -s -F "file=@sample.wav;type=audio/wav" -F "language=ru" \
     http://127.0.0.1:8765/v1/audio/transcriptions
# {"text":"Привет!"}
```

Требования к аудио: **WAV, 16 кГц, моно, PCM16**. Ответ — `{"text": "..."}`, при
`response_format=text` — просто текст.

Поведение сервера, которое надо учитывать: ленивая загрузка модели (~1.5–2 с на GPU),
автовыбор устройства, idle-выгрузка через 30 минут (`WHISPER_IDLE_SECONDS`), завершение по
исчезновению `WHISPER_PARENT_PID`. Сервер — общий ресурс: **читать и переиспользовать можно,
менять файлы в `.whisper-local/` нельзя** (ими пользуется DSH).

Проверено на этой машине (перепроверить самому, не верить на слово):

- `XDG_SESSION_TYPE=wayland`, `XDG_CURRENT_DESKTOP=KDE`, Plasma `6.8.2`, KWin;
- есть: `ydotool`, `wl-copy`/`wl-paste`, `parec`, `pw-record`, `notify-send`, `qdbus6`,
  `busctl`, `python-gobject` + `gtk4`, `pyside6 6.12`;
- нет: `wtype`, `kdotool`, `xdotool`;
- в репозиториях CachyOS есть `gtk4-layer-shell`, `libayatana-appindicator`, `pyside6`.
- в сессии есть `org.kde.kglobalaccel` и `org.freedesktop.portal.Desktop` (KDE-бэкенд).

## Что за софт должен получиться

**Режимы работы**

- Глобальный хоткей: toggle (нажал — пишет, нажал — стоп и вставка). По умолчанию
  предложить `Meta+Alt+D` (или `Alt+M`), настраиваемо.
- Push-to-talk (удержание) — опционально, если хоткей-механизм это позволяет.
- Кнопка в трее: «Записать / Остановить», «Настройки», «Открыть лог», «Выход».

**HUD во время записи**

- Маленькое окно без рамки, всегда сверху: индикатор уровня, таймер `0:07`, кнопки
  «Стоп» и «Отмена» (Esc — отмена без вставки).
- По остановке: «Распознаю…» на 0.3–2 с, затем HUD исчезает, текст вставляется.

**Вставка текста**

- Основной путь: текст в буфер обмена + эмуляция `Ctrl+V` в активное окно; опция
  «восстановить прежний буфер после вставки».
- Альтернатива: посимвольный ввод (ydotool) — только как опция, для кириллицы он капризен.
- Если вставка невозможна — оставить текст в буфере и показать уведомление «текст скопирован».

**Настройки** (окно или вкладка)

- хоткей; язык (`ru`, `en`, `auto`, …); адрес сервера; команда запуска сервера;
  режим вставки; автозапуск при входе; звуковой сигнал старт/стоп; порог тишины/длительность.

**Первый запуск**

- Проверить `GET /health`; если сервер не отвечает — предложить запустить `run.sh`
  (кнопка «Запустить распознавание»), показать прогресс загрузки модели.
- Если модели нет — предложить скачать (явное действие пользователя, не молча).

## Технические требования

1. **Стек**: Python 3.12 + GTK4/PyGObject **или** PySide6 6.12 (оба уже установлены).
   GTK4 выигрывает по весу и даёт `gtk4-layer-shell` для HUD; Qt даёт готовый трей и
   `KGlobalAccel`-интеграцию через DBus. Выбрать по результатам проверки хоткея и
   вставки, обосновать в README. Никакой Electron.
2. **Аудио**: запись через `pw-record`/`parec` в 16 кГц моно PCM16 (подпроцесс, аккуратное
   завершение по SIGINT), либо `sounddevice`/`pipewire` — что надёжнее в вашей проверке.
3. **STT-клиент**: HTTP multipart на `127.0.0.1:8765`, таймауты, ретрай 1 раз, понятные
   ошибки (сервер не запущен / 500 / пустой ответ / нет речи).
4. **Глобальный хоткей на Wayland** — главный риск. Проверить по порядку и выбрать рабочее:
   - регистрация в `org.kde.kglobalaccel` через DBus (component + shortcut);
   - `org.freedesktop.portal.GlobalShortcuts` (KDE-бэкенд);
   - fallback, который обязан работать всегда: CLI `whisper-dictate toggle` + инструкция
     назначить шорткей в System Settings → Shortcuts → Custom.
   В README честно написать, что проверено, а что нет.
5. **Вставка на Wayland**: `ydotool` требует `uinput` (root или группа `input` и запущенный
   `ydotoold`) — **не настраивать молча**, спросить пользователя. Дефолт — буфер + `Ctrl+V`
   через ydotool, с проверкой, что вставка реально сработала (по желанию: сверка активного
   окна). Все стратегии — за флагом в конфиге.
6. **HUD на Wayland**: клиент не может сам позиционировать окно. Варианты: `gtk4-layer-shell`
   (если доступен и работает на KWin) либо обычное маленькое `always-on-top` окно, которое
   размещает композитор. Описать выбранное поведение.
7. **Трей**: StatusNotifierItem через `libayatana-appindicator` (GTK) — KDE его поддерживает.
8. **Конфиг**: `~/.config/whisper-dictate/config.toml`; автозапуск —
   `~/.config/autostart/whisper-dictate.desktop`.
9. **Сервис**: если `8765` уже отвечает — использовать его; если нет — запустить
   `run.sh` и дождаться `/health`. Чужой экземпляр (запущенный DSH) не убивать.
10. **Приватность**: никаких сетевых вызовов, кроме `127.0.0.1`; аудио не писать на диск
    дольше, чем нужно для запроса (или писать только при включённом debug).
11. **Ресурсы**: после простоя освобождать память/VRAM (полагаться на idle-выгрузку сервера
    или останавливать его самому по таймауту).

## Пакет и установка

- `PKGBUILD` для Arch/CachyOS: `pkgname=whisper-dictate`, установка в `/usr/bin`,
  `/usr/share/applications`, `/usr/share/icons/hicolor/...`.
- Зависимости: `python`, `pipewire`, `wl-clipboard`, `libnotify`, плюс один из тулкитов:
  `python-gobject` + `gtk4`, либо `pyside6`; опционально `ydotool` (вставка),
  `gtk4-layer-shell` (HUD), `libayatana-appindicator` (трей). Все есть в репозиториях CachyOS.
- `systemd --user` юнит (опционально) или autostart — на выбор, описать.
- Модель **не** кладём в пакет: используем существующую по конфигу или качаем в
  `~/.local/share/whisper-dictate/models` по явной команде.

## Тесты и критерии приёмки

1. `whisper-dictate --transcribe sample.wav` → корректный русский текст (юнит-тест клиента).
2. Запись 5–10 с через `pw-record` → распознавание → текст вставлен в тестовое окно
   (`kwrite`/`kate`/`gedit`), проверить на реальной Wayland-сессии.
3. Хоткей срабатывает из другого приложения (браузер, терминал), HUD появляется и исчезает.
4. Esc во время записи — отмена, ничего не вставляется.
5. Трей: меню, смена состояния иконки, выход завершает все подпроцессы.
6. Перезапуск DSH и его закрытие не ломают приложение; приложение не требует DSH.
7. Задержка: 10–20 с речи на GPU — распознавание ≤ 1.5 с (сервер уже даёт ~0.8–1.2 с).
8. `ps`/`ss` после выхода: не осталось висящих `parec`/`pw-record`/python-процессов
   (кроме общего сервера, если он был запущен до).
9. README: установка, настройка хоткея, известные ограничения Wayland, как удалить.

## Ограничения и предостережения

- Wayland: глобальные хоткеи и синтетический ввод — не «просто работают»; проверяйте на
  живой сессии, а не в теории.
- `ydotool`/`uinput` требует прав; любые изменения в системе (группы, `ydotoold`, systemd)
  согласовывать с пользователем.
- Не трогать `~/.dsh/profiles/**`, не менять `.whisper-local/**`, не перезапускать DSH.
- Не скачивать модели и не ставить пакеты без явного согласия.
- Если что-то из ТЗ противоречит фактам на машине — факты важнее: опишите расхождение и
  предложите решение.
